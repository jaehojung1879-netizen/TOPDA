# 톺다 편집 원칙

> 이 문서는 톺다의 한국어 콘텐츠를 쓰고 고칠 때 따르는 기준입니다.
> 새 글을 쓸 때, 기존 글을 고칠 때, 생성기 템플릿의 문구를 바꿀 때 모두 적용합니다.
> `reports/editorial-ux-audit.md` 가 "지금 무엇이 잘못됐는가"라면, 이 문서는 "앞으로 어떻게 쓰는가"입니다.

**최종 갱신**: 2026-08-01

---

## 0. 사이트의 성격을 먼저 정한다

톺다는 **부동산 지식을 모아 놓은 곳이 아니라, 거래 전에 비용과 절차를 확인하는 도구 사이트**입니다.
이 문장이 모든 편집 판단의 기준입니다.

| | 이렇게 쓴다 | 이렇게 쓰지 않는다 |
|---|---|---|
| 사이트 정체성 | 계산기와 공공데이터가 중심, 글은 결과를 읽는 방법 | "부동산의 모든 것을 정리한 지식 허브" |
| 글의 역할 | 사용자의 판단을 돕는 설명 | 검색 유입을 위한 정보 나열 |
| 권위의 근거 | 법령 조문·공식 통계·기준일 | "전문가", "완벽", "필수" |
| 첫 화면의 목표 | "지금 무엇을 확인해야 하는지 알겠다" | "정보가 많다" |

글을 하나 더 쓰는 것보다, 기존 글에서 근거 없는 문장 하나를 지우는 것이 낫습니다.
페이지 수를 늘려 문제를 해결하지 않습니다.

## 1. 기본 문체

1. **존댓말 설명체**를 씁니다. 명령형·구호형 문장은 쓰지 않습니다.
2. **홍보 문구보다 사용자가 해야 할 행동을 먼저** 씁니다.
   - ✗ `톺다에서 부동산 거래의 디테일을 빠짐없이 정리하자`
   - ✓ `매매·전월세 비용을 계산하고, 계약부터 잔금일까지 확인할 항목을 단계별로 살펴보세요.`
3. **한 문장에는 하나의 판단만** 담습니다. 접속사로 서너 개를 잇지 않습니다.
4. **결론을 먼저 쓰되, 근거와 적용 조건을 바로 이어서** 씁니다.
   - ✓ `1세대 1주택 비과세는 12억까지입니다. 다만 보유·거주 요건을 채운 경우이며, 12억을 넘는 부분은 안분해 과세합니다(소득세법 제89조).`
5. **"무조건", "절대", "압도적", "완벽", "필수", "가장 좋다"** 는 객관적 근거가 있을 때만 씁니다.
   법령상 의무일 때는 `…해야 합니다(○○법 제○조)` 처럼 근거를 붙여 쓰고, 관행일 때는 `대체로`, `일반적으로` 로 낮춥니다.
6. **지역·시점·개별 조건에 따라 달라지는 내용은 그 조건을 명시**합니다.
   - ✗ `학군지는 학기 직전 거래가 폭증합니다.`
   - ✓ `학기 시작 직전에 임대차 수요가 몰리는 지역이 있습니다. 실제로 그런지는 해당 시군구의 월별 거래량으로 확인하세요.`
7. **법률·세무·금융 내용은 법령 또는 공식 기관 자료와 연결**합니다. 링크는 그 주장이 등장하는 절 가까이에 둡니다.
8. **시장 관행과 법적 기준을 구별**합니다.
   - 법적 기준: `임차권등기명령은 임대차보호법 제3조의3에 따라 신청합니다.`
   - 시장 관행: `공정 진행률에 맞춘 분할 지급이 흔합니다. 법으로 정해진 비율은 없습니다.`
9. **모르는 사실을 상식처럼 채우지 않습니다.** 확인할 수 없으면 문장을 지웁니다.

## 2. 쓰지 않는 표현

전수 검색 대상입니다. 꼭 필요한 경우가 아니면 제거하거나 구체적인 문장으로 바꿉니다.

### 2-1. 과장·홍보형

| 금지·축소 | 대체 |
|---|---|
| A부터 Z까지 / A to Z | 구조와 절차 / 신청부터 실행까지 |
| 한눈에 | (삭제) 또는 `한 화면에서` (실제로 한 화면일 때만) |
| 한 번에 | (삭제) 또는 `같은 화면에서` |
| 처음부터 끝까지 | (삭제) |
| 완벽 가이드 / 완벽 정리 | (주제명) 구조 / (주제명) 계산 방법 |
| 총정리 | 정리 / (삭제) |
| 핵심만 | 먼저 확인할 항목 |
| 이것만은 | 확인할 조항 |
| 3종 세트 | 보호 요건 세 가지 (숫자가 실제 의미 있을 때만) |
| N분 만에 | (삭제) |
| 빠뜨리면 손해 | (삭제) — 정산 항목 / 확인 항목 |
| 돈이 갈리는 | 금액 차이가 나는 |
| 무조건 확인 | 확인하세요 |
| 반드시 알아야 할 | (삭제) |
| 실전 꿀팁 | (삭제) |
| 전문가 수준 / 전문가처럼 | (삭제) |
| 인사이트 | 판단 기준 / 지표 |
| 로드맵 | 순서 / 타임라인 |
| 대시보드 (반복) | 계산기 / 표 / 지표 (실제 형태를 씀) |
| 정리했습니다 (소개문 끝) | (삭제) — 무엇을 확인할 수 있는지로 대체 |
| 도와드립니다 / 해결해 드립니다 | (삭제) — 근거 없는 서비스 약속 |

### 2-2. 장식

- ✨ 🚀 ✅ 등 장식용 이모지: **사용하지 않습니다.**
  경고 콜아웃의 `⚠` 처럼 의미가 있는 기호는 예외입니다.
- `NEW` 배지 상시 노출: **사용하지 않습니다.** 새 것임을 알려야 하면 날짜를 씁니다.
- 링크 끝의 `→`: 링크 제목이 이미 행동을 설명하면 붙이지 않습니다.
- 영문 eyebrow (`GUIDE`, `TOOLS` 같은 섹션 위 소문자 라벨): 섹션 제목이 이미 있으면 붙이지 않습니다.

### 2-3. 숫자형 제목

숫자형 제목 자체를 금지하지는 않습니다. **정확한 항목 수가 실제로 중요할 때만** 씁니다.
검색 클릭을 위한 숫자라면 업무·판단 중심 제목으로 바꿉니다.

| 변경 전 | 변경 후 |
|---|---|
| 좋은 집 보는 눈 12가지 | 매물을 볼 때 확인할 기준 |
| 등기부등본 핵심만 5분 안에 읽기 | 등기부등본에서 먼저 확인할 항목 |
| 전세 보증금 지키는 3종 세트 | 전세보증금 보호 요건 확인하기 |
| 잔금일 정산, 빠뜨리면 손해 보는 5가지 | 매매 잔금일 정산 항목 |
| 주택담보대출 A to Z | 주택담보대출 구조와 신청 절차 |
| 인테리어, 한 주제씩 처음부터 끝까지 | 인테리어 자재와 계약 기준 |

**URL은 바꾸지 않습니다.** 제목을 바꿀 때는 다음을 함께 맞춥니다.

- `<title>`
- `<meta name="description">`
- `og:title` / `og:description` / `twitter:title` / `twitter:description`
- JSON-LD `headline` / `description` / BreadcrumbList 의 마지막 `name`
- 사이트 안에서 그 페이지를 가리키는 모든 앵커 텍스트
- `_meta/build_search_index.py` 가 만드는 검색 인덱스 (생성기 재실행)

## 3. 사실성

### 3-1. 처리 순서

주장을 만나면 다음 순서로 처리합니다.

1. **공식 통계·원문이 있고 주장과 정확히 일치하면** → 출처와 기준 시점을 붙인다.
2. **일반적인 선호나 관행이면** → 단정 대신 판단 요소로 바꾼다.
3. **지역·단지마다 달라 일반화하기 어려우면** → 조건을 명시한다.
4. **검증할 수 없으면** → 삭제한다.

출처가 페이지 상단에 나열되어 있다는 이유로 개별 주장이 검증된 것으로 보지 않습니다.
중요한 수치·법령·제도 변경은 **해당 문장 또는 해당 절 가까이에** 근거를 둡니다.

### 3-2. 특히 조심할 문장 유형

- 근거 없이 비율을 제시하는 문장 (`분쟁의 90%가 …`)
- 가격이 오른다거나 거래가 급증한다고 단정하는 문장
- 특정 평면·향·층·학군을 일률적으로 우수하다고 단정하는 문장
- "표준", "로열층", "안전판", "프리미엄" 을 고정 기준처럼 쓰는 문장
- 시장 관행을 법적 의무처럼 쓰는 문장
- 특정 상품·제도가 항상 유리하다고 읽히는 문장

### 3-3. 쓰면 안 되는 것

운영자가 확인할 수 없는 다음 항목은 **어떤 경우에도 새로 만들지 않습니다.**

- 자격·경력·전문가 감수 여부
- 사용자 수·방문자 수·만족도
- 응답 시간·처리 건수
- 출처 없는 통계·비율·평균

## 4. 글 페이지 구조

### 4-1. 상단

기본으로 두는 것은 이것뿐입니다.

- 카테고리 (breadcrumb)
- 제목
- 1~2문장의 소개
- 게시일 / 최근 검토일
- 작성 주체
- 필요한 경우 기준 시점

여러 개의 배지를 동시에 붙이지 않습니다. 배지는 **카테고리·상태·기준일 등 메타데이터**에만 씁니다.

### 4-2. 요약 블록

`한 줄 결론` 이라는 고정 레이블은 쓰지 않습니다. 글 성격에 맞는 이름을 고릅니다.

- `먼저 확인할 내용` — 개념 설명 글
- `이 글의 판단 기준` — 비교·선택 글
- `적용 대상` — 제도·자격 글
- `계산 전에 확인할 조건` — 계산기와 연결된 글
- `계약 전에 확인할 항목` — 계약 실무 글

억지로 강한 결론을 만들지 않습니다. **독자가 글을 읽기 전에 알아야 할 조건을 2~4개 이내로** 제시합니다.

### 4-3. 목차

- 본문 절(`<h2>`)이 **6개 이상일 때만** 표시합니다.
- 항목이 12개를 넘으면 상위 절만 노출합니다.
- `01.`, `02.` 번호는 **순서가 중요한 절차형 글에서만** 씁니다.
- 참고자료·FAQ·관련 글은 본문 목차의 주요 절과 같은 수준으로 나열하지 않습니다.
- 모바일에서는 기본 접힘.

### 4-4. 본문

- 한 절의 **첫 문장이 그 절의 핵심 판단**입니다.
- 한 문단을 굵은 글씨로 조각내지 않습니다. 굵은 글씨는 **조건·숫자·결론**에만.
- 표는 **비교가 필요할 때만** 씁니다. 일반 설명을 표로 바꾸지 않습니다.
- 서로 다른 글에 같은 문장 구조와 같은 마무리를 반복하지 않습니다.
- FAQ 는 실제 검색·게시판 질문이나 본문에서 해결하기 어려운 질문이 있을 때만 둡니다.
  **모든 글에 FAQ 를 붙이지 않습니다.**

### 4-5. 출처와 날짜

- 법령·통계를 직접 쓴 절에는 **가까운 위치에** 출처를 둡니다.
- 상단에는 `최근 검토일` 과 주요 기준만 간결하게 표시합니다.
- 하단에는 **실제로 사용한 출처만** 정리합니다. 템플릿 때문에 안 쓴 기관 링크를 넣지 않습니다.
- **`내용 검토일`(사람이 내용을 확인한 날)과 기술 수정일(HTML 변경일)을 구분**합니다.
  화면에 노출하는 것은 내용 검토일입니다.
- 읽기 시간은 실제 글자 수로 계산하거나, 신뢰할 수 없으면 표시하지 않습니다.

### 4-6. 하단

- 가장 직접적으로 연결되는 **도구 1~2개만** 강조합니다.
- 관련 글은 **간단한 텍스트 목록**으로 둡니다. 카드 3개 그리드를 고정으로 붙이지 않습니다.
- 같은 링크가 본문·사이드·하단에 반복되지 않게 합니다.
- 댓글 영역이 있으면 관련 콘텐츠보다 먼저 강제하지 않습니다.

## 5. 시각 규칙

### 5-1. 컴포넌트

같은 페이지 안에서 **카드 유형은 최대 2종류**입니다. 공통 컴포넌트는 다음 수준으로 유지합니다.

| 컴포넌트 | 용도 |
|---|---|
| primary action | 그 페이지에서 가장 중요한 도구 하나 |
| secondary action | 보조 행동 |
| editorial link list | 제목 + 한 줄 설명의 텍스트 목록 (기본값) |
| utility card | 도구 진입 카드 |
| data panel | 숫자·표·차트를 담는 판 |
| notice / callout | 경고·주의·기준일 안내 |
| article source | 출처 목록 |
| table | 비교표 |
| form / result | 계산기 입력·결과 |

**목록이 기본이고 카드가 예외입니다.** 카드를 쓰기 전에 목록으로 충분한지 먼저 확인합니다.

### 5-2. 색과 깊이

- **파란색은 의미가 있는 곳에만**: 행동 버튼, 링크, 현재 상태.
  배경·아이콘·배너의 장식 색으로 쓰지 않습니다.
- 배경은 흰색과 중성 회색 중심.
- 그라데이션은 브랜드를 강조하는 한두 곳을 제외하고 쓰지 않습니다.
- 그림자보다 **여백·타이포그래피·얇은 구분선**.
- 일반 콘텐츠 카드는 **떠오르지 않습니다** (`translateY` 호버 금지).
- 중요한 도구와 일반 링크는 시각적 강도를 분리합니다.

### 5-3. 타이포그래피

- Pretendard 유지.
- 본문 **400~500**, 제목 **650~750**. 800 weight 는 쓰지 않습니다.
- 본문 가독 폭 **680~760px**. 정보 허브는 그보다 넓게.
- 표와 계산기 입력은 360px 화면에서 가로 넘침·글자 압축이 없어야 합니다.

## 6. 영문 페이지

- 한국어를 기계 번역하지 않습니다. 같은 페이지가 있으면 **정보구조와 링크 목적**을 맞춥니다.
- 영어권 사용자에게 의미 없는 한국식 마케팅 표현은 직역하지 않습니다.
- `A to Z`, `ultimate guide`, `everything you need`, `complete guide` 는 쓰지 않습니다.
- 영문 페이지에서 한국어 페이지로 넘어가는 링크는 **그렇다고 표시**합니다 (`(Korean)`).
- 번역이 미완성인 언어의 색인 정책은 기존 기준을 유지합니다.

## 7. 바꾸지 않는 것

편집 작업에서 **건드리지 않는** 영역입니다.

- 계산기 계산식·세율·요율·대출 한도 로직
- 실거래가·공시가격·세대수 수집 및 집계 로직
- 추정·보간하지 않고 결측값을 드러내는 데이터 원칙
- 단지 페이지의 색인 품질 게이트와 `noindex,follow` 정책
- canonical, hreflang, sitemap, JSON-LD, robots 정책
- 기존 공개 URL 과 내부 링크
- GA4·네이버 애널리틱스·AdSense·Supabase
- 게시판·댓글·체크리스트·localStorage
- 한국어/영어 페이지의 언어별 연결
- 키보드 탐색·포커스 표시·aria 속성
