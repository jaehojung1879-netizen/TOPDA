## 1. 홈 (`site/index.html`)

**사용자의 주요 목적** — 이번 거래에서 돈이 얼마나 드는지, 지금 단계에서 뭘 확인해야 하는지 알아내기.

**현재 첫 화면에서 먼저 보이는 것**
1. `부동산, 하나하나 톺아보다` (브랜드 구호)
2. `톺다에서 부동산 거래의 디테일을 빠짐없이 정리하자` (명령형 자기계발 문장)
3. 통합 검색 바
4. 아이콘 카드 6개 (매매/전세·월세/대출·금융/인테리어/이사·입주/경매·공매)

계산기는 스크롤을 내려야 나온다. 사이트의 핵심 가치가 첫 화면에 없다.

**중복** — 카테고리 6종이 홈·`guides.html`·푸터에 세 번 반복. 시세정보 섹션의 `맞춤 내집 찾기`가 계산기 섹션과 같은 `hero-calc-card` 컴포넌트를 그대로 재사용해 두 섹션이 구분되지 않는다.

**반복 카드·배지** — `cat-tile` × 6 → `hero-calc-card` × 1 → `sector-card` × 5 → `hero-calc-card` × 1 → `tool-card` × 2 → `tool-card` × 4. 카드 컴포넌트 4종, 총 19개 카드.

**과장 표현** — `빠짐없이 정리하자`, `한눈에`, `조건만 넣으면 단지를 점수로 추천`, 체크리스트 부제 `등기·정산 30가지`·`보증금 지킴 3종`.

**출처가 필요한 단정** — 없음(홈은 링크 허브라 주장 문장이 적다).

**삭제·통합·축약** — 첫 화면 아이콘 카드 6개, `sector-card`, `tool-card` 그리드, 섹션마다 반복되는 `전체 … →` 링크.

**유지할 것** — `home:issues` 마커 구조(운영자가 쓰지 않은 주에는 섹션을 만들지 않는 원칙), 검색 폼, 푸터 면책.

**수정 대상** — `site/index.html`, `site/assets/styles.css`

**우선순위** — **P0**

### 실제 수정
- 히어로를 `집을 거래할 때 필요한 비용과 절차` + `매매·전월세 비용을 계산하고, 계약부터 잔금일까지 확인할 항목을 단계별로 살펴보세요.` 로 교체. 명령형 구호 삭제.
- 첫 화면 기본 행동을 **종합 계산기**로 승격(`home-primary` 단일 액션). 검색은 그 아래 보조 행동으로 내림.
- 두 번째 영역을 **상황 진입점 6개**의 편집형 목록(`entry-list`)으로 교체. 아이콘 카드 그리드 삭제.
- 이후 영역을 `자주 쓰는 계산기`(텍스트 목록) → `공식 실거래 데이터`(2열) → `거래 단계별 체크리스트`(단계 목록) 순으로 재배치. 섹션마다 카드 그리드를 쓰지 않고 목록·2열·강조 영역을 섞음.
- `hero-calc-card`·`sector-card`·`tool-card`·`cat-tile` 사용 제거(클래스는 CSS 호환용으로만 유지).

## 2. 가이드 허브 (`site/guides.html`)

**목적** — 내 상황에 맞는 설명 글 찾기.

**첫 화면** — `가이드` 라는 한 단어 제목 + 배너 이미지 + `기본 개념부터 시장·투자 인사이트까지, … 3단계 학습 경로로 정리했습니다.`

**중복** — 카테고리 6종 카드가 홈과 완전히 동일. `최근 이슈` 3편이 각 카테고리 페이지에도 하이라이트 카드로 다시 등장. `전체 글 34편 →` 링크가 섹션마다 반복.

**반복 카드·배지** — `card` 3 + `card` 3 + `hub-tool` 6 + `card` 8 + `card` 8 + `card` 4 = 32개 카드. 글 카드마다 배지 2개(`기본`/`심화`/`전문가` + 카테고리)가 겹쳐 붙는다.

**과장·AI스러운 표현**
- `1단계 기본기 / 2단계 실전·심화 / 3단계 전문가` — 사이트의 실제 작성·감수 구조와 맞지 않는다. `about.html` 에는 "운영자는 부동산 관련 자격을 보유하고 있지 않으며, 외부 전문가 감수 절차를 두고 있지 않습니다"라고 적혀 있다. **'전문가 가이드'라는 라벨은 이 고지와 정면으로 충돌한다.**
- `시장·투자 인사이트`, `실전에서 돈이 갈리는 것`, `전문가처럼`, `판단의 근거를 세우는 글`
- `가이드 보기 →` 가 6개 카드 전부에 반복

**출처가 필요한 단정** — `전문가 가이드는 시세정보의 실거래·전세가율 데이터와 함께 읽을 때 가장 유용합니다.`

**삭제·통합** — 3단계 학습 경로 안내 카드 3개(본문 앵커로만 가는 카드), 카테고리 카드 6종(홈과 중복), 반복 CTA.

**유지** — 최근 이슈 3편 배치, 전체 글 링크.

**수정 대상** — `site/guides.html`

**우선순위** — **P0**

### 실제 수정
- 3단계(기본기/실전·심화/전문가) 구조를 **거래 단계 6구간**으로 교체: `매물 탐색 전` / `계약 전 확인` / `계약 후 준비` / `대출·세금 확인` / `잔금일` / `입주·이사 이후`.
- 각 구간을 카드 그리드가 아니라 `editorial link list`(제목 + 한 줄 설명)로 표현. 배지 제거.
- 학습경로 안내 카드 3개 삭제(같은 페이지 앵커로만 가던 중복).
- 카테고리 6종은 카드 그리드 대신 상단 한 줄 `subnav` 로 축소 — 홈·카테고리 페이지와의 3중 중복 해소.
- lead 를 `거래 단계에 따라 지금 확인할 내용을 골라 보세요. 각 글은 계산기 결과를 어떻게 읽을지 설명합니다.` 로 교체.

## 3. 카테고리 페이지 (`site/categories/*.html` 5개)

**목적** — 매매/임대차/대출/이사/경매 각 영역에서 지금 쓸 도구와 읽을 글 찾기.

**첫 화면** — 배너 이미지 + 영문식 eyebrow(`매매 가이드`) + 한 단어 h1 + lead + `전체 스케줄 보기 ↓` 버튼 + 탭.

**중복** — `가이드`/`계산기` 탭 안의 카드가 `guides.html`·홈·글 하단 `관련 계산기` 와 반복. 같은 계산기가 한 페이지에서 탭·스케줄·출처 섹션에 최대 3번 등장.

**반복 카드·배지** — `topic-card` 6 + `topic-card` 6 + `source-card` 4~6 + `card` 3(관련 글). `자세히 보기 →` 가 카드마다 반복.

**과장·AI스러운 표현**
- `대시보드 ✨ NEW`, `일정 ✨ NEW` — 이모지 + 상시 NEW 배지
- `Chart.js 도넛으로 비중 시각화` — 사용자 문구에 구현 기술 노출
- `관심 있는 주제를 골라 깊이 있게`, `세금·중개수수료·잔금일·전체 비용을 한 번에`
- `8개 주제를 최신 시장 이슈부터 등기 완료까지 정리했습니다`

**출처가 필요한 단정** — `분쟁의 90%가 특약에서 시작됩니다.` (sale.html)

**삭제·통합** — `✨`, `NEW`, 구현 기술 문구, 카드마다의 CTA 문구, `전체 스케줄 보기` 퀵내비.

**유지** — 탭 구조(가이드/계산기 분리는 유용), 공식 자료 섹션, 스케줄 타임라인.

**수정 대상** — `site/categories/{sale,lease,loan,moving,auction}.html`

**우선순위** — **P0**

### 실제 수정
- 페이지 순서를 지시대로 재구성: ① 이 페이지에서 할 수 있는 일 → ② 지금 상황에 맞는 도구 → ③ 단계별 가이드 → ④ 공식 자료와 기준일 → ⑤ 일정/체크리스트.
- `✨`·`NEW`·`Chart.js 도넛으로 비중 시각화` 전량 제거.
- `자세히 보기 →` / `계산하기 →` / `가이드 보기 →` 반복 CTA 제거. 링크 제목이 행동을 설명하도록 문구 조정.
- `분쟁의 90%가 특약에서 시작됩니다` → `계약서 본문보다 특약에서 분쟁이 자주 생깁니다. 아래 조항은 문구를 미리 정해 두는 편이 낫습니다.`
- 도구 목록을 `topic-card` 그리드 → `tool-list`(제목 + 한 줄 설명 + 얇은 구분선)로 교체. 페이지당 카드 유형 2종 이하로 축소.

## 14. 확인할 수 없어 보류한 항목

실제 자료나 운영자 판단이 없으면 해결할 수 없는 것만 남깁니다.

1. **`interior/` 의 자재 단가 범위** — `기준 시점 2026.05`, `시장 관행 기반 참고치` 라고만 되어 있고 산출 근거가 없습니다. 조달청 가격정보나 실제 견적 표본으로 대체하지 않는 한, 숫자의 신뢰도를 높일 방법이 없습니다. 현재는 전제(시점·범위의 성격)를 문장으로 명시하는 선까지만 처리했습니다.
2. **`X분 읽기`** — `_meta/add_post_extras.py` 가 한글 400자/분으로 계산하므로 근거는 있으나, 400자/분이 이 사이트 독자에게 맞는 값인지는 확인할 수 없습니다. 유지하되 값의 근거를 바꾸려면 운영자 판단이 필요합니다.
3. **`beta` 표식 유지 여부** — 무엇이 베타인지는 운영자만 정의할 수 있습니다. `about.html` 에 "데이터 수록 범위가 전국을 다 덮지 못하고 기능이 계속 추가되는 상태" 라고 적었으나, 다른 의미였다면 그 문장을 고쳐야 합니다.
4. **게시판 데스크톱 내비 노출** — 게시판을 주 내비에 둘지는 운영 정책입니다. 현재는 모바일 메뉴와 푸터에만 두는 기존 다수 페이지 규칙을 따랐습니다.
